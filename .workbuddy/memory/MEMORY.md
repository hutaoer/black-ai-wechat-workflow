## 工作流约定

- 三模式：A=每日9点定时热点推送3候选（automation-1791091700033）；B=自命题（用户给题→素材包确认→成稿）；C=题目+大纲（用户给题+结构→核料→成稿，大纲是结构最高权威）
- 尺度：批现象不碰制度，犀利但落点建设性；成稿红线见 STYLE_GUIDE.md 第八节
- 产出规范：1000字以内（用户明确要求“补充/深化/融合”时可放宽至1600字，社保文已验证一次）、posts/YYYYMMDD-标题/index.md、附数据来源、附“三个关键判断”
- **交付格式：只出 Markdown（index.md）。不做 HTML 版、不做公众号排版 HTML**（用户 2026-10-17 明确要求，后续一律不再产出 html）
- 终稿回存 posts/ 后需 diff 分析，迭代风格指南（2026-11-03 已对《流言》一篇执行一次）
- **事实与用户记忆冲突时，先摆证据、确认后再动笔**；不替当事人“和解”，真实结局优先
- **用户说“补充/梳理/重构”是加内容，不是减内容**：原有辩证段、核心比喻、金句论证链必须保留（2026-11-03 重构时误删，已写进指南第五节）
- **全局标点规则（2026-11-03）：中文引用文本一律用中文双引号 “ ” 包裹，不用半角 ASCII 直引号**。适用于正文/标题/小标题/数据来源/所有模式与所有改稿；代码与命令行不受约束。已写入 WORKFLOW.md 第二步、STYLE_GUIDE.md 第六节与自检清单，并已把《流言》终稿及两份流程文档的存量引号统一
